## 1. KI の商品ポジション（確定）

**KI は「AI 競馬予想 ＋ 長期会員クラブ」である。**

| 項目 | 決定 |
|---|---|
| 馬育成アプリ | ❌ **作らない** |
| KAA 型の「馬を育成して行動ポイントを稼ぐ」仕組み | ❌ **作らない** |
| ネイティブアプリ化 | ❌ **今回のスコープにしない** |
| KAA 等の別リポジトリの育成・ゲーム機能のコピー | ❌ **禁止** |
| KI の中身 | ✅ AI 競馬予想（馬単・南関東4場＋中央競馬）＋ **長期会員クラブ** |

🔴 **KI リワードは「継続の対価」であり、ゲーム的な行動報酬ではない。**
ログイン報酬・クリック報酬・育成・ミッション・ガチャ等を KI へ持ち込まない。
積み上がる根拠は **Premium を継続していること、ただ一つ**である。

## 3. 制度の全体像（確定した構造）

新設する制度は次の 6 本。**構造は確定、数値は未確定**（§7）。

| # | 制度 | 確定した内容 |
|---|---|---|
| M-1 | **継続価格ロック** | 契約中は、その会員が**加入した時点の契約価格を維持できる**。将来の新規価格を変更できるよう、**契約時価格を会員単位で保持する** |
| M-2 | **継続プレゼント** | 会員継続期間に応じて**実物**のプレゼントを受け取れる |
| M-3 | **選べるプレゼント** | 条件達成時に**複数候補から選べる**。景品カタログは**設定・データ駆動**で将来変更できる |
| M-4 | **長期会員優遇** | 長期会員ほどリワード・交換待遇を優遇できる構造を持つ |
| M-5 | **会員ランク** | **Bronze / Silver / Gold / Platinum** の 4 段階 |
| M-6 | **継続記念品** | 長期継続の節目で、通常のポイント交換とは**別枠**の記念特典を提供できる |

### 3.1 M-1 継続価格ロック

- 契約時の請求額（Stripe Price の実額）を **会員レコードに保存**する。
- 保存するのは「新規価格を将来変更しても、契約中の会員の請求額を維持する」ためである。
- 🔴 **Stripe の Price を後から書き換えて既存会員の請求額を変えない。**
  新規価格は **新しい Price を作って切り替える**（既存サブスクは旧 Price のまま）。
  したがってロックの実効は Stripe 側にあり、KI 側の保存値は **表示と監査のための写し**である。
- 🔴 **未確定（Claude が決めない）**: 解約後の再加入価格 / 価格ロックの復活条件（§7）。

### 3.2 M-5 会員ランク（Bronze / Silver / Gold / Platinum）

🔴 **ランク差は「リワード・プレゼント・長期待遇」に限定する。**

| 差を付けてよいもの | 差を付けてはいけないもの |
|---|---|
| リワードの積み上がり方 | ❌ **予想の精度** |
| プレゼントの選択肢・交換待遇 | ❌ **買い目の内容・点数** |
| 継続記念品 | ❌ **有料情報の質・公開範囲** |
| — | ❌ **tier（`free` / `light` / `premium`）の権限** |

- ランクは `premium` の**継続月数**から決まる（構造）。昇格月数は**未確定**（§7）。
- ランクは **entitlement に影響しない**。`canSeeMarks` / `canSeeBetting` はランクを受け取らない。

### 3.3 KI リワード

- **Premium を継続することで自動的に積み上がる。**
- ❌ ログイン報酬・育成・クリック報酬ではない。
- UI では「積み上がり」を感じられるようにする。ただし次を厳守する。

🔴 **表現規約（違反はテストで落とす）**

| 使ってよい | 使ってはいけない |
|---|---|
| KI リワード残高 | ❌ 貯金 / 預金 / 積立金 |
| 今月の積み上げ | ❌ 現金 / キャッシュ / 円換算 |
| 次のプレゼントまであと◯◯ | ❌ 換金 / 出金 / 払い戻し（リワード文脈で） |
| ポイント | ❌ 残高（円）/ 口座 |

- 🔴 **リワードは現金・預金ではない。換金可能な残高として実装しない。**
  金額（円）への換算表示を行わない。出金・送金・譲渡の経路を作らない。

## 4. 申込ページ（`/pricing`）の二本柱

`/pricing` は「予想機能一覧＋価格」だけではなく、**二本柱**にする。

```
柱1: 予想サービスの価値      （既存のマトリクス・月額プラン）
柱2: 続けるほど会員価値が積み上がる（本制度）
```

柱2 に出してよい訴求（**確定しているものだけ**）:

- 月額 ¥3,980
- KI リワードが毎月積み上がる
- Bronze → Silver → Gold → Platinum
- 選べるプレゼント
- 長期継続記念品
- 継続価格ロック
- 次の特典までの進捗

🔴 **未確定のポイント数・景品内容・必要月数を UI へ出さない。**
架空値・例示値・「たとえば〜」も出さない。未確定箇所は **「準備中」** と表示する。

### 6.1 fail-closed の定義（本制度）

| 状況 | 挙動 |
|---|---|
| 昇格月数が未設定 | ランクを**返さない**（`configured: false`）。Bronze へ倒さない |
| 付与ポイント設定が未設定 | 残高・積み上げを**返さない**（`pending`） |
| 景品カタログが `draft` / 空 | 交換可能プレゼントを**出さない** |
| 契約価格が未保存 | 「準備中」。¥3,980 を**推測で当てはめない** |
| 永続化が無効 / 未設定 | `unavailable`。**「達成しました」と表示しない** |
| 交換履歴が読めない | 「準備中」。🔴 **「まだ受け取られた特典はありません」と言い切らない**（受け取り済みの特典を「無い」と伝えることになる）。0 件と断定してよいのは台帳が読めたときだけ |

## 8. 法務・会計（KI コード内で断定しない）

🔴 **景品表示法・会計処理の最終判断を KI のコード内で独自に断定しない。**
以下は **数値確定前に法令上の確認が必要**な項目である。確認結果が出るまで実装しない。

| # | 確認が必要な項目 | なぜ |
|---|---|---|
| L-1 | 総付景品 / 一般懸賞のどちらに当たるか | 景品類の限度額が変わる（景品表示法） |
| L-2 | 「取引価額」の算定（月額 ¥3,980 か、年間合計か） | 景品の**最高額・総額の上限**が決まる |
| L-3 | 景品の提供価額の算定方法 | L-1 / L-2 の上限に対する適否 |
| L-4 | 「選べるプレゼント」が懸賞に当たらないか | 選択制の設計次第で扱いが変わりうる |
| L-5 | ポイント（リワード）の会計処理 | 未使用ポイントの負債計上・収益認識（契約負債） |
| L-6 | ポイント失効の扱い | 失効益の認識時期（TBD-6 と連動） |
| L-7 | 特定商取引法上の表示（`/tokushoho`）の更新要否 | 継続特典・失効条件を表示する必要があるか |
| L-8 | 資金決済法（前払式支払手段）に当たらないことの確認 | 🔴 **換金・譲渡・金額換算を実装しない**前提を崩さないため |
| L-9 | 発送先住所の取得・保管（個人情報保護法） | TBD-12 |

🔴 **L-8 が本制度の設計上の生命線である。**
リワードは **現金・預金ではなく、換金可能な残高として実装しない**。
円への換算表示・出金・譲渡・第三者への移転を作らない（§3.3 の表現規約と一体）。

## 9. 禁止事項

1. 未確定の数値（TBD-1〜TBD-8）を、既定値・例示値・プレースホルダとして**コードや UI に置くこと**
2. リワードを**金額（円）に換算して表示**すること / 換金・出金・譲渡の経路を作ること
3. ランク差を **予想の精度・買い目の内容・有料情報の質**に持ち込むこと
4. ランクや継続月数を **entitlement / tier / 認可**の判断材料にすること
5. ライトプランの購入導線の復活 / 会場別アクセス（`venueAccess`）の復活
6. KAA 等の別リポジトリの **育成・ゲーム機能**を KI へ持ち込むこと
7. 景品表示法・会計処理の判断を **コードのコメントや docs で断定**すること（§8 は「確認が必要」と書くまで）
8. 会員データの**本番スキーマ変更・本番 write** を承認なしに行うこと（`docs/MEMBERSHIP_DATA_MIGRATION.md`）
