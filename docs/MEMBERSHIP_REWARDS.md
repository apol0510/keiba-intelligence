## 3. 制度の全体像（確定した構造）

新設する制度は次の 6 本。**構造は確定、数値は未確定**（§7）。

| # | 制度 | 確定した内容 |
|---|---|---|
| M-1 | **継続価格ロック** | 契約中は、その会員が**加入した時点の契約価格を維持できる**。将来の新規価格を変更できるよう、**契約時価格を会員単位で保持する** |
| M-2 | **継続プレゼント** | 会員継続期間に応じて**実物**のプレゼントを受け取れる |
| M-3 | **選べるプレゼント** | 条件達成時に**複数候補から選べる**。景品カタログは**設定・データ駆動**で将来変更できる |
| M-4 | **長期会員優遇** | 長期会員ほどリワード・交換待遇を優遇できる構造を持つ |
| M-5 | **会員ランク** | **Bronze / Silver / Gold / Platinum** の 4 段階 |
| M-6 | **継続記念品** | 長期継続の節目で、通常のポイント交換とは**別枠**の記念特典を提供できる |

### 3.1 M-1 継続価格ロック

- 契約時の請求額（Stripe Price の実額）を **会員レコードに保存**する。
- 保存するのは「新規価格を将来変更しても、契約中の会員の請求額を維持する」ためである。
- 🔴 **Stripe の Price を後から書き換えて既存会員の請求額を変えない。**
  新規価格は **新しい Price を作って切り替える**（既存サブスクは旧 Price のまま）。
  したがってロックの実効は Stripe 側にあり、KI 側の保存値は **表示と監査のための写し**である。
- 🔴 **未確定（Claude が決めない）**: 解約後の再加入価格 / 価格ロックの復活条件（§7）。

### 3.2 M-5 会員ランク（Bronze / Silver / Gold / Platinum）

🔴 **ランク差は「リワード・プレゼント・長期待遇」に限定する。**

| 差を付けてよいもの | 差を付けてはいけないもの |
|---|---|
| リワードの積み上がり方 | ❌ **予想の精度** |
| プレゼントの選択肢・交換待遇 | ❌ **買い目の内容・点数** |
| 継続記念品 | ❌ **有料情報の質・公開範囲** |
| — | ❌ **tier（`free` / `light` / `premium`）の権限** |

- ランクは `premium` の**継続月数**から決まる（構造）。昇格月数は**未確定**（§7）。
- ランクは **entitlement に影響しない**。`canSeeMarks` / `canSeeBetting` はランクを受け取らない。

### 3.3 KI リワード

- **Premium を継続することで自動的に積み上がる。**
- ❌ ログイン報酬・育成・クリック報酬ではない。
- UI では「積み上がり」を感じられるようにする。ただし次を厳守する。

🔴 **表現規約（違反はテストで落とす）**

| 使ってよい | 使ってはいけない |
|---|---|
| KI リワード残高 | ❌ 貯金 / 預金 / 積立金 |
| 今月の積み上げ | ❌ 現金 / キャッシュ / 円換算 |
| 次のプレゼントまであと◯◯ | ❌ 換金 / 出金 / 払い戻し（リワード文脈で） |
| ポイント | ❌ 残高（円）/ 口座 |

- 🔴 **リワードは現金・預金ではない。換金可能な残高として実装しない。**
  金額（円）への換算表示を行わない。出金・送金・譲渡の経路を作らない。

## 4. 申込ページ（`/pricing`）の二本柱

`/pricing` は「予想機能一覧＋価格」だけではなく、**二本柱**にする。

```
柱1: 予想サービスの価値      （既存のマトリクス・月額プラン）
柱2: 続けるほど会員価値が積み上がる（本制度）
```

柱2 に出してよい訴求（**確定しているものだけ**）:

- 月額 ¥3,980
- KI リワードが毎月積み上がる（**100 pt / 月**）
- Bronze → Silver → Gold → Platinum（**0 / 3 / 12 / 24 か月**）
- 選べるプレゼント（**600 pt / 1,200 pt** の 2 段階）
- 長期継続記念品（**12 か月・24 か月**）
- 継続価格ロック
- 次の特典までの進捗

🔴 **UI に出してよい数値は §7.1 の確定値だけ。**
**景品の品目・必要ポイント以外の未確定値（TBD-3b / TBD-9 / TBD-10 / TBD-12）は出さない。**
架空値・例示値・「たとえば〜」も出さない。未確定箇所は **「準備中」** と表示する。

### 6.1 fail-closed の定義（本制度）

| 状況 | 挙動 |
|---|---|
| 継続月数が不明（起点が未保存 / TBD-9 未確定） | ランクを**返さない**（`monthsKnown: false`）。Bronze へ倒さない |
| 昇格月数の設定が壊れている（順序逆転・欠落など） | ランクを**返さない**。既定値へ黙って戻さない |
| 台帳が読めない | 残高・積み上げを**返さない**（`pending`）。0 pt と言い切らない |
| 記念品の月（12 / 24 か月） | 通常交換の候補を**出さない**（`blockedByMilestone`。§7.4） |
| 解約後 90 日を過ぎている | ポイントは **失効**（`expired`）。残高を表示しない |
| 景品カタログが `draft` / 空 | 交換可能プレゼントを**出さない** |
| 契約価格が未保存 | 「準備中」。¥3,980 を**推測で当てはめない** |
| 永続化が無効 / 未設定 | `unavailable`。**「達成しました」と表示しない** |
| 交換履歴が読めない | 「準備中」。🔴 **「まだ受け取られた特典はありません」と言い切らない**（受け取り済みの特典を「無い」と伝えることになる）。0 件と断定してよいのは台帳が読めたときだけ |

### 7.2 なぜ ¥796 なのか（保守ラインの根拠）

総付景品（購入者全員に提供する景品類）は、**取引価額が 1,000 円以上なら取引価額の 10 分の 2** が上限。
月額 ¥3,980 に対して **¥796**。

- これは「取引価額＝月額」という **いちばん厳しい読み方**での上限である。
  年額で見ればさらに余裕があるため、**¥796 に収めておけばどちらの読み方でも収まる**。
- したがって **取引価額の解釈を確定させる必要がない**（§8 の確認を待たずに運用できる）。
- 🔴 **¥796 を超える景品を出す判断をした時点で、取引価額の確認が必要になる。**
- 送料は景品価額に含めない整理が一般的だが、**含めて計算しても収まる水準**にしておくこと。

### 7.3 全員同一条件を保つ（総付を維持する）

- **抽選・くじ・先着などの偶然性を入れない。** 入れると一般懸賞になり別の上限が適用される。
- 「選べるプレゼント」は **同じ条件を満たした人に同じ候補を提示して選ばせるだけ**にする。
- 上位ランクの優遇は **候補の幅（`minRank`）**で行い、**必要ポイントの割引では行わない**
  （同じ景品を人により違う条件で出すと説明が複雑になるため）。

### 7.4 記念品と通常交換を同月に重ねない

12 か月目・24 か月目は記念品の月とし、**その月は通常のポイント交換を受け付けない**。

- 目的は 1 か月あたりの景品類を ¥796 の枠に収めること（記念品と交換品の合算を避ける）。
- 実装: `catalog.js` の `isMilestoneMonth(months)` が真の月は
  `exchangeView` が `blockedByMilestone` を返し、交換候補を出さない。

## 8. 法令上の前提（保守ラインの内側で運用する）

🔴 **景品表示法・会計処理の最終判断を KI のコード内で断定しない。**
ただし本制度は §7.2 の **保守ライン（1 点 ¥796 以内・全員同一条件）**の内側に収めてあるため、
**運用開始のために確認を待つ必要がある項目は無い**。

### 8.1 保守ラインを維持するために守ること

| # | 守ること | 崩れたときに起きること |
|---|---|---|
| S-1 | 景品 1 点を **¥796 以内**に収める | 取引価額（月額か年額か）の確認が必要になる |
| S-2 | 記念品と通常交換を **同月に重ねない** | 1 か月の景品類が合算され S-1 を超えうる |
| S-3 | **抽選・くじ・先着を入れない**（全員同一条件＝総付を維持） | 一般懸賞となり別の上限が適用される |
| S-4 | リワードを **換金・譲渡・円換算しない** | 前払式支払手段（資金決済法）の議論に入る |

S-1〜S-4 はコード側の静的ガードとテストで固定してある。

### 8.2 判断が必要になったときだけ確認する項目

**いま確認しなくてよい。** 下記の設計変更をしたくなったときに、初めて確認する。

| # | いつ必要になるか | 確認すること |
|---|---|---|
| L-1 | ¥796 を超える景品を出したくなったとき | 継続的役務における「取引価額」の算定（月額か年間合計か） |
| L-2 | 抽選・先着を入れたくなったとき | 一般懸賞の上限（取引価額の20倍・総額は売上予定総額の2%） |
| L-3 | 送料が高い景品を扱うとき | 送料を景品価額に含めるかどうか |
| L-4 | 交換の実運用を始めるとき | `/tokushoho` に継続特典・失効条件・解約時の扱いの表示が要るか（TBD-12 と同時） |
| L-5 | 決算期 | 未使用ポイントの会計処理（引当・契約負債）。**税理士に確認**。§7 の残高上限と 90 日失効により見積りは容易 |

🔴 **失効条件・解約時の扱いは、制度開始と同時に規約へ明記すること。**
後から付けると不利益変更になる。
