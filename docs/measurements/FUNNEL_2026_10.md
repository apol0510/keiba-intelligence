## 2. 実装（本 PR）

### 2.1 GA4 の URL 浄化（許可リスト・fail-closed）

- `src/lib/analytics/pageLocation.js` の `sanitizeAnalyticsUrl`: クエリは **utm_* / 広告クリック ID（gclid ほか）/
  `ref` / `checkout` / `resume`** だけ残し、他はすべて落とす。ハッシュも落とす。許可キーでも `@` を含む値は落とす。
- BaseLayout の GA4 初期化を `ga4BootstrapScript()` に置き換え、`gtag('set', {page_location, page_referrer})` を
  **config（= 最初の page_view）より前に** 実行する。以後のイベントもこの値を使う。
- 関数は inline スクリプトへ関数文字列のまま埋め込む（test と本番で同じコード）。

### 2.2 ファネルイベント（`ki_*`・既存の計測契約と同じ形式）

| イベント | 引数（列挙値のみ） | 場所 |
|---|---|---|
| `ki_pricing_link_click` | `placement`（nav / footer / body / `data-ki-placement`） | 全ページ（`/pricing` 宛てリンク） |
| `ki_signup_result` | `result`: sent / resent / already / mismatch / error | `/register` |
| `ki_checkout_click` | `plan`, `resumed`: yes / no | `/pricing` |
| `ki_purchase_auth_open` | `plan` | `/pricing`（未ログイン → メール確認） |
| `ki_purchase_email_result` | `plan`, `result`: sent / error | `/pricing` |
| `ki_checkout_redirect` | `plan` | `/pricing`（Stripe へ移動する直前） |
| `ki_checkout_error` | `plan` | `/pricing` |
| `ki_checkout_cancelled` | なし | `/pricing?checkout=cancelled` |
| `ki_login_verify_result` | `result`: ok / expired / used / not_found / error, `intent`: purchase / none | `/auth/verify` |
| `ki_checkout_return` | なし | `/mypage?checkout=success` |
| `ki_checkout_synced` | `result`: changed / pending | `/mypage`（権限反映） |

- 🔴 `trackFunnel` は **固定のイベント名・固定のキー・英数字の値** 以外を送らない（email・token は形式で弾かれる）。
- gtag が無い（広告ブロック等）ときは何もしない。計測の失敗で導線を止めない。
- 導線・文言・価格・CTA の数と位置は変えていない。

### 2.3 検証

- `src/lib/analytics/funnelEvents.test.mjs`（14 件。`npm run test:billing` → `npm run build` に組み込み）:
  token / email の除去、inline 初期化を vm で実行して `set` が `config` より前・dataLayer に token / email が無いこと、
  許可リスト外の名前・キー・値を送らないこと、**全イベントがページに配線されていること**、呼び出し引数に email / token / セッション値が無いこと。
- ブラウザ（Playwright・localhost の astro dev・関数応答と GA の通信は差し替え）1280px / 375px で 22 項目:
  `/auth/verify?token=…&email=…` の page_location が `/auth/verify` だけになる / dataLayer に token・email なし /
  `/pricing` で cancelled → click → auth_open → email_result の順に発火・utm と checkout は残る / ホームの料金リンク / 登録結果 / 既存の画面表示は不変。

## 3. 実験として扱う

| 項目 | 内容 |
|---|---|
| 問題 | 決済より上流のファネルが 1 段も計測されておらず、どこで失っているか判断できない。計測に email・token が混入していた |
| baseline | 2026-09: 決済 8 件・¥31,840。上流の各段は 0 イベント（未計測）。GA4 への PII 送信: 確認メール経由の全ログイン |
| 仮説 | 各段を数えると、料金ページ到達 → 申し込み → メール確認完了 → Checkout 完了のどこかに、売上上限を決めている落ち込みが見つかる |
| 介入 | §2（URL 浄化＋11 イベント）。表示・導線は不変 |
| 期待結果 | (1) GA4 に token / email を含む page_location / page_referrer が新規に入らない (2) 各段のイベント件数が日次で取れ、段ごとの通過率を出せる |
| 評価期間 | 2026-10-20 〜 2026-11-16（28 日）。最初の 7 日で各イベントの発火を確認し、28 日で段ごとの通過率を出す |
| 判断 | 計測は維持。通過率が最も低い段を次の改善候補にする（1 回に 1 変更）。PII 混入が見つかれば即座に許可リストを狭める |

🔴 母数が小さい（決済は月 1 桁）ため、28 日でも統計的な判断はできない。段ごとの件数を記録して定性的に優先順位を付ける。

### 3.1 評価に必要な運用（本 PR の範囲外・別途登録）

- GA4 の探索で上記イベントを使ったファネルを作り、`ki_checkout_redirect` / `ki_signup_result` を key event にする（GA4 管理画面）。
- 計測を自動で読むため、KI の GA4 プロパティに読み取り専用のサービスアカウントを追加する（人の操作）。

- 確認メールのリンク自体が `&email=` を含む（`register-free.js`）。ページ側では送らなくなったが、リンクから email を外すのは認証経路の変更として別 task。
